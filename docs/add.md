# Add or correct a source

Bring a repository, release, research note, forum post, community venue or a correction to an existing entry. One useful source is enough.

## Three ways to send it

1. **Open an issue.** Use [Source or correction](https://github.com/xulfr/om-firmware-atlas/issues/new?template=source.yml), or [Project discovery or update](https://github.com/xulfr/om-firmware-atlas/issues/new?template=project.yml) for a whole project. A contributor will take it from there.
2. **Ask an AI agent.** Give an agent with repository access the [source prompt](how-it-works.md#copyable-prompts). It will update the records and open a pull request for review.
3. **Make the change yourself.** Follow the [contribution steps](https://github.com/xulfr/om-firmware-atlas/blob/main/CONTRIBUTING.md) and the [record format](https://github.com/xulfr/om-firmware-atlas/blob/main/maintenance/record-format.md).

[How the Atlas works](how-it-works.md) follows a source from its URL to the published site.

## What belongs here

Sourced camera and project records, precise observations, explanations of shared research, tool setup references, contribution destinations and community links. The Atlas does not host firmware, decoded images, executable tools or whole chat transcripts. It also does not list a repository that publishes firmware (a stock or modified update file, or a decoded image) on a branch, tag or release; such a source will be declined.

For a repository, point to the relevant release, branch, issue or report as well as the README; a README alone may miss the work. Missing evidence means unknown, not failure, and a new version does not inherit an older package's results.

## From a discussion to documentation

A discussion can lead to a useful finding. Share a link to the specific post or message, with the camera and project it concerns. A server invitation alone is not a technical source.

- Keep the author and date, and say whether the result is firsthand or repeated.
- Summarise the finding with its limits; a short attributed summary beats a transcript.
- Public links and permission to republish are separate. Private messages and channels need permission for what is published.
- Leave out serial numbers and unrelated personal details.

To add or correct a [community venue](../views/community/index.md), send it as a source. A venue listing helps people find each other; it is not evidence that any modification works.
